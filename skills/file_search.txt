## Golden rule: ALWAYS find first — 3 steps

**NEVER assume a file's full path from its name alone.** Follow these 3 steps in order:

```bash
# Step 1 — locate the file in the mounted evidence
find '{evidence}' -iname 'pdf.pdf' -type f 2>/dev/null
# → /forensics/part006/Users/JohnDoe/Desktop/pdf.pdf   (found → go to Step 3)
# → (no output)                                          (not found → go to Step 2)

# Step 2 — ONLY if Step 1 returned NOTHING: the file may be inside a nested VHD/VMDK
#           Find the virtual disk file, then search ALL its partitions in ONE command.
find '{evidence}' \( -iname '*.vhd' -o -iname '*.vmdk' \) -type f 2>/dev/null
# → /forensics/part006/Windows/System32/config/SYSTEM.vhd

# DO NOT run mmls first to inspect partitions — run the full loop below directly.
# Search ALL partitions at once — NEVER run mmls alone or check partitions one by one.
# ALWAYS use -i vhd with fls on VHD files; without it, dynamic VHDs return empty.
# Run this EXACT loop and wait for the "FOUND" line before proceeding.
VHD='/forensics/part006/Windows/System32/config/SYSTEM.vhd'
mmls "$VHD" 2>/dev/null | awk 'NR>5 && $2~/[0-9]/{print $3}' | while read start; do
  offset=$(( 10#$start ))
  result=$(fls -i vhd -r -o "$offset" "$VHD" 2>/dev/null | grep -i 'pdf.pdf')
  [ -n "$result" ] && echo "FOUND offset=$offset: $result"
done
# The loop prints one line per match, e.g.:
#   FOUND offset=<ACTUAL_OFFSET>: r/r <ACTUAL_INODE>:   pdf.pdf
# Use ONLY the offset and inode printed by the loop above — NEVER use values from examples.

# Extract the file using icat — replace <ACTUAL_OFFSET> and <ACTUAL_INODE> with loop output:
icat -i vhd -o <ACTUAL_OFFSET> "$VHD" <ACTUAL_INODE> > /exports/pdf.pdf
stat -c "%s" /exports/pdf.pdf
# Always compute all three — hash type in the question is not always what it says:
md5sum /exports/pdf.pdf    # 32-char hash
sha1sum /exports/pdf.pdf   # 40-char hash
sha256sum /exports/pdf.pdf # 64-char hash

# Step 3 — use the full path returned by find (or the extracted file) for further commands
stat -c "%s" '/forensics/part006/Users/JohnDoe/Desktop/pdf.pdf'
md5sum '/forensics/part006/Users/JohnDoe/Desktop/pdf.pdf'
```

## What is generic file search?
`find` locates files by name, extension, path pattern, size, or type anywhere in the evidence image. `file` identifies the true file type from magic bytes (ignores the extension). Use these when you need to discover what files exist before doing deeper analysis.

## Usage examples
```bash
# Find all PDF files (case-insensitive)
find '{evidence}' -iname '*.pdf' -type f 2>/dev/null

# Find files by name pattern
find '{evidence}' -iname '*password*' -type f 2>/dev/null

# Find all executable files
find '{evidence}/USERS' -iname '*.exe' -o -iname '*.bat' -o -iname '*.ps1' 2>/dev/null | head -50

# Find large files (over 50MB) — useful for hidden media
find '{evidence}/USERS' -type f -size +50M 2>/dev/null

# Identify true file type of a suspicious file (ignores extension)
file '{evidence}/USERS/<username>/Desktop/<document.pdf>'

# Find all Office documents
find '{evidence}/USERS' \( -iname '*.doc' -o -iname '*.docx' -o -iname '*.xls' -o -iname '*.xlsx' \) -type f 2>/dev/null

# Find recently created files in user folders
find '{evidence}/USERS' -type f -printf '%TY-%Tm-%Td %TH:%TM %p\n' 2>/dev/null | sort -r | head -30
```

## Email files (.eml)
RFC 2822 headers span multiple lines — a header value continues on the next line
if it starts with whitespace. NEVER use plain `grep` alone on .eml files because it
only returns lines containing the pattern and silently drops continuation lines.

```bash
# Read the first 50 lines to see ALL headers with their continuation lines
head -n 50 '<path/to/file.eml>'

# Show a specific header AND its continuation lines (2 lines of context after)
grep -A 2 '^Received:' '<path/to/file.eml>'

# Find all Received headers with full context
grep -A 3 '^Received' '<path/to/file.eml>'
```


## Tips
- Always use `-iname` (case-insensitive) since Windows filenames may have mixed case on a Linux mount
- Add `2>/dev/null` to suppress permission errors on system directories
- `file` is useful for detecting files with wrong or missing extensions (e.g., a `.jpg` that is actually a ZIP)
- For very large results, pipe to `head -50` or save to `/exports/` with `>`
- Combine `find` with `-printf '%TY-%Tm-%Td %TH:%TM %p\n'` to include modification dates in the output
