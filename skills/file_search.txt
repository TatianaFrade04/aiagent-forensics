## Golden rule: one combined search command

**NEVER assume a file's full path.** Run this single command — it searches mounted partitions first, then falls through to the VHD automatically if not found:

```bash
TARGET='<target_file>.ext'
FILE=$(find '/forensics' -iname "$TARGET" -type f 2>/dev/null | head -1)
if [ -n "$FILE" ]; then
  echo "FOUND: $FILE"
  stat -c "%s" "$FILE"
else
  echo "Not in mounted partitions — searching VHD..."
  VHD=$(find '{evidence}' \( -iname '*.vhd' -o -iname '*.vmdk' \) -type f 2>/dev/null | head -1)
  echo "VHD: $VHD"
  mmls "$VHD" 2>/dev/null | awk 'NR>5 && $2~/[0-9]/{print $3}' | while read start; do
    offset=$(( 10#$start ))
    result=$(fls -i vhd -r -o "$offset" "$VHD" 2>/dev/null | grep -i "$TARGET")
    [ -n "$result" ] && echo "FOUND in VHD offset=$offset: $result"
  done
fi
```

This prints either:
- `FOUND: /forensics/part006/...` + size → done, use the path directly
- `FOUND in VHD offset=<N>: r/r <INODE>:   <target_file>.ext` → extract with icat:

**CRITICAL — fls `*` prefix means DELETED:**
```
r/r * 61:   <filename>   ← * = DELETED — content may be empty or overwritten — DO NOT USE
r/r 64:     <filename>   ← no * = ACTIVE file — USE THIS INODE
```
When fls returns multiple entries for the same filename, ALWAYS use the entry WITHOUT `*`.
A `*` entry is a deleted/unallocated inode — extracting it gives empty or garbage content.

```bash
# Replace <ACTUAL_OFFSET> and <ACTUAL_INODE> with the values printed above — NEVER use example values
# Use ONLY the inode WITHOUT * (the active file)
icat -i vhd -o <ACTUAL_OFFSET> "$VHD" <ACTUAL_INODE> > /exports/<target_file>.ext
stat -c "%s" /exports/<target_file>.ext
md5sum /exports/<target_file>.ext    # 32-char hash
sha1sum /exports/<target_file>.ext   # 40-char hash
sha256sum /exports/<target_file>.ext # 64-char hash
```

## Hash verification — CRITICAL rules

**Step 1: identify the algorithm from the stated hash length BEFORE computing:**
| Length | Algorithm | Command |
|--------|-----------|---------|
| 32 hex | MD5       | `md5sum <file>` |
| 40 hex | SHA1      | `sha1sum <file>` |
| 64 hex | SHA256    | `sha256sum <file>` |

**Step 2: if the stated hash length does NOT match the claimed algorithm → answer is immediately `false`.**
Example: question says "MD5 hash is C1F95108A34228535A9262085E784D7C3E27FC68"
→ count chars: 40 → that is SHA1 length, NOT MD5 → answer = false (no computation needed)

**Step 3: if the length is correct, compute the right hash and compare:**
```bash
# When question says "MD5" — ALWAYS use md5sum, NEVER sha1sum
md5sum /exports/<file> | awk '{print toupper($1)}'

# When question says "SHA1" — use sha1sum
sha1sum /exports/<file> | awk '{print toupper($1)}'
```

**NEVER use sha1sum when asked for MD5, and never use md5sum when asked for SHA1.**

## What is generic file search?
`find` locates files by name, extension, path pattern, size, or type anywhere in the evidence image. `file` identifies the true file type from magic bytes (ignores the extension). Use these when you need to discover what files exist before doing deeper analysis.

## Usage examples
```bash
# Find all PDF files (case-insensitive)
find '{evidence}' -iname '*.pdf' -type f 2>/dev/null

# Find files by name pattern
find '{evidence}' -iname '*password*' -type f 2>/dev/null

# Find all executable files
find '{evidence}/USERS' -iname '*.exe' -o -iname '*.bat' -o -iname '*.ps1' 2>/dev/null | head -50

# Find large files (over 50MB) — useful for hidden media
find '{evidence}/USERS' -type f -size +50M 2>/dev/null

# Identify true file type of a suspicious file (ignores extension)
file '{evidence}/USERS/<username>/Desktop/<document.pdf>'

# Find all Office documents
find '{evidence}/USERS' \( -iname '*.doc' -o -iname '*.docx' -o -iname '*.xls' -o -iname '*.xlsx' \) -type f 2>/dev/null

# Find recently created files in user folders
find '{evidence}/USERS' -type f -printf '%TY-%Tm-%Td %TH:%TM %p\n' 2>/dev/null | sort -r | head -30
```

## Email files (.eml)
RFC 2822 headers span multiple lines — a header value continues on the next line
if it starts with whitespace. NEVER use plain `grep` alone on .eml files because it
only returns lines containing the pattern and silently drops continuation lines.

```bash
# Read the first 50 lines to see ALL headers with their continuation lines
head -n 50 '<path/to/file.eml>'

# Show a specific header AND its continuation lines (2 lines of context after)
grep -A 2 '^Received:' '<path/to/file.eml>'

# Find all Received headers with full context
grep -A 3 '^Received' '<path/to/file.eml>'
```


## Tips
- Always use `-iname` (case-insensitive) since Windows filenames may have mixed case on a Linux mount
- Add `2>/dev/null` to suppress permission errors on system directories
- `file` is useful for detecting files with wrong or missing extensions (e.g., a `.jpg` that is actually a ZIP)
- For very large results, pipe to `head -50` or save to `/exports/` with `>`
- Combine `find` with `-printf '%TY-%Tm-%Td %TH:%TM %p\n'` to include modification dates in the output
