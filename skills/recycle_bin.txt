## What is the Recycle Bin?
When a file is deleted via Windows Explorer (not Shift+Delete), it goes to `$RECYCLE.BIN\<SID>\`. Each deleted file creates two entries:
- `$I<hash>` — metadata file: original full path, file size, deletion timestamp
- `$R<hash>` — the actual deleted file content (recoverable)

The SID in the path identifies which user deleted the file.

## Forensic use cases
- Find files that were deliberately deleted by a suspect
- Recover the original path of deleted files
- Determine when files were deleted
- Identify which user deleted each file (via SID)
- Recover deleted file content

## CRITICAL: recovering original paths from $I files

`$I` files store the original Windows path in UTF-16LE encoding (Windows Vista+ format).
`strings` without flags only extracts ASCII — use `strings -e l` to extract UTF-16LE strings.
Then use `grep ':'` to find Windows drive-letter paths like `C:\Users\...` — NO backslash in grep pattern.

WRONG (plain strings misses UTF-16LE paths):
  `find ... | while read f; do strings "$f" | grep ':'; done`  → may return empty or only partial fragments

WRONG (breaks command parsing — never use xargs bash -c with backslash patterns):
  `find ... | xargs -I {} bash -c 'strings {} | grep -oP "^.*\\"'`  → "unexpected EOF" errors

RIGHT — use strings -e l (little-endian 16-bit = UTF-16LE):
```bash
find '/forensics/part006/$RECYCLE.BIN' -name '$I*' -type f 2>/dev/null | while read f; do strings -e l "$f" | grep ':'; done | sort -u
```

ALWAYS use `while read f; do strings -e l "$f" | grep ':'; done` for extracting original paths.
NEVER use `xargs -I {} bash -c '...'` — complex quoting inside bash -c always fails.

## CRITICAL: identifying which user deleted files

The SID IS the directory name in the path — it does NOT need to be extracted from the binary.
Example path: `/forensics/part006/$RECYCLE.BIN/S-1-5-21-...-1004/$IABFQJP.txt`
→ User SID is `S-1-5-21-...-1004` (the directory between `$RECYCLE.BIN/` and the `$I` filename)

To list unique SIDs: `find '/forensics/part006/$RECYCLE.BIN' -mindepth 1 -maxdepth 1 -type d 2>/dev/null`

## Usage examples
```bash
# List all $I metadata files (one per deleted item)
find '/forensics/part006/$RECYCLE.BIN' -name '$I*' -type f 2>/dev/null

# Recover original paths from ALL $I files — strings -e l extracts UTF-16LE paths, grep ':' finds Windows paths
find '/forensics/part006/$RECYCLE.BIN' -name '$I*' -type f 2>/dev/null | while read f; do strings -e l "$f" | grep ':'; done | sort -u

# List all deleted items with timestamps — use find -printf (NOT stat)
find '/forensics/part006/$RECYCLE.BIN' -name '$I*' -printf '%TY-%Tm-%Td %TH:%TM %p\n' 2>/dev/null | sort

# Identify which users deleted files: SID directories under $RECYCLE.BIN
find '/forensics/part006/$RECYCLE.BIN' -mindepth 1 -maxdepth 1 -type d 2>/dev/null

# List actual deleted file contents ($R files)
find '/forensics/part006/$RECYCLE.BIN' -name '$R*' -type f 2>/dev/null | head -30

# Copy a recoverable deleted file to exports
cp '/forensics/part006/$RECYCLE.BIN/S-1-5-21-1171287513-3642516788-2358256967-1004/$RABFQJP.txt' /exports/recovered_file.txt
```

## Tips
- The SID `S-1-5-21-...-1004` etc. identifies the user — correlate with SAM hive or user directory names
- `$I` files are small binary files; use `strings` to read the original path embedded in them
- `$R` files have the same content as the original deleted file — you can copy and open them
- Shift+Delete bypasses the Recycle Bin — those files are NOT here and require carving tools
