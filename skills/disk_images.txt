## TWO types of disk — discover both before starting

| Question refers to… | What to use | How to find it |
|---|---|---|
| **Physical disk** (schema, disk GUID, partition GUIDs, cluster size of a physical partition) | Raw disk image file | `find` for `ewf1` or raw image formats |
| **Nested virtual disk** (VHD/VMDK file inside the evidence) | VHD/VMDK file path | `find` inside the mounted evidence directories |

**CRITICAL: mounted partition directories are NOT disk images.**
Mounted filesystems are directories — opening them as binary files always fails with `IsADirectoryError`.
Always use the raw image file (step 0 below) for binary-level analysis.

## Step 0 — Discover the environment (ALWAYS run first)

```bash
# Find the raw physical disk image.
# EWF images are mounted and exposed as a file named 'ewf1'.
# Raw images may have extensions: .dd, .img, .raw, .001
DISK=$(find / -maxdepth 6 -name 'ewf1' -type f 2>/dev/null | head -1)
[ -z "$DISK" ] && DISK=$(find / -maxdepth 6 \( -name '*.dd' -o -name '*.img' -o -name '*.raw' \) \
    -not -path '*/proc/*' -not -path '*/sys/*' -type f 2>/dev/null | head -1)
echo "Physical disk image: $DISK"

# Find where the evidence partitions are mounted (for file-level access)
mount | grep -iE 'loop|fuseblk|ntfs|ext[234]' | awk '{print NR". "$1" → "$3}'
```

Once you have `$DISK`, use it for all physical-disk operations below.

## A — Physical disk analysis

Questions about "the physical disk": partition schema, disk GUID, partition GUIDs, cluster size.

```bash
# ── STEP 1: partition schema (answer is on the FIRST LINE of mmls output) ──────
DISK=$(find / -maxdepth 6 -name 'ewf1' -type f 2>/dev/null | head -1)
mmls "$DISK" | head -3
# Output first line examples:
#   "GUID Partition Table (EFI)"  → schema = GPT
#   "DOS Partition Table"          → schema = MBR
# Data partitions: rows with a numeric Slot (000, 001…). Skip Meta and -------.
# 1st data partition = lowest numeric Slot, 2nd = next numeric Slot, etc.

# ── STEP 2: cluster size for a specific partition ───────────────────────────────
# Read the Start value for the target partition from mmls output, then:
start=<start_value_from_mmls>          # e.g. the value in the Start column
offset=$(( 10#$start ))                # MANDATORY: strips leading zeros (octal trap)
fsstat -o "$offset" "$DISK" | grep -iE 'cluster size|volume name|sector size'
# "Cluster Size: N bytes" → cluster size in bytes for that partition

# ── STEP 3: capacity of a partition ─────────────────────────────────────────────
# Get the Length value from mmls for the partition:
len=<len_value_from_mmls>
echo "Capacity: $(( 10#$len * 512 )) bytes"
# Length is in 512-byte sectors. Multiply by 512 for bytes. NEVER use fsstat totals.
```

### Disk GUID and partition GUIDs (GPT format)

**The two GUID types use different byte representations — do NOT mix them:**
- **Disk GUID** → raw hex bytes as stored in the file (no field reordering).
- **Partition GUIDs** → standard Windows UUID notation (bytes_le reordering of the first three fields).

```bash
# CRITICAL: $DISK must be set before running this block (from Step 0 above).
# Use << EOF (no quotes) so $DISK expands inside the heredoc.
python3 << EOF
import uuid

disk = "$DISK"   # bash variable expands here — DO NOT quote EOF on the opening line

with open(disk, 'rb') as f:

    # Disk GUID — GPT header at LBA 1 (byte 512), GUID at offset 56 (16 bytes).
    # Output: raw hex bytes as stored in the file.
    f.seek(512)
    gpt = f.read(512)
    print('Disk GUID:', gpt[56:72].hex().upper())

    # Partition GUIDs — entry array at LBA 2 (byte 1024), 128 bytes per entry.
    # Unique GUID is at offset 16 within each entry.
    # Output: UUID bytes_le (standard Windows GUID display format).
    f.seek(1024)
    for i in range(128):
        entry = f.read(128)
        if entry[:16] == b'\x00' * 16:   # all-zero type GUID = empty slot
            break
        guid = uuid.UUID(bytes_le=entry[16:32])
        print(f'Partition {i+1}: {str(guid).upper().replace("-", "")}')
EOF
```

## B — Nested virtual disk analysis (VHD/VMDK inside evidence)

```bash
# 1. Find the virtual disk file inside the mounted evidence.
#    Use the mount points found in Step 0 as the search root.
#    ALWAYS assign to $VHD — never retype the filename (Linux is case-sensitive).
EVIDENCE_ROOT="<mount_point_from_step0>"
VHD=$(find "$EVIDENCE_ROOT" -type f \( -iname '*.vhd' -o -iname '*.vmdk' -o -iname '*.dd' -o -iname '*.img' \) 2>/dev/null | head -1)
echo "$VHD"   # verify the exact path before proceeding
# For a named file (e.g. "System.vhd"):
#   VHD=$(find "$EVIDENCE_ROOT" -iname 'system.vhd' -type f 2>/dev/null | head -1)

# 2. Identify the image type
file "$VHD"

# 3. List data partitions — pipe mmls through awk, NEVER run plain mmls
#    Columns: $1=row, $2=SlotType(Meta/-------/00:NN), $3=Start, $4=End, $5=Length
#    Filter: $2~/[0-9]/ keeps only data partitions
mmls "$VHD" 2>/dev/null | awk 'NR>5 && $2~/[0-9]/{print $1, "start="$3, "len="$5}'
#    Example output:
#      004: start=<start_sector> len=<len_sectors>
#      006: start=<start_sector> len=<len_sectors>
#    If fsstat returns "Cannot determine file system type" for a row, skip it —
#    it's a reserved area. Count only rows where fsstat SUCCEEDS as numbered partitions.

# 4. Find partition by volume label AND calculate its capacity — complete workflow
#    Run this loop to check EVERY data partition until the right Volume Name is found.
mmls "$VHD" 2>/dev/null | awk 'NR>5 && $2~/[0-9]/{print $2, $3, $5}' | while read slot start len; do
    offset=$(( 10#$start ))
    label=$(fsstat -i vhd -o "$offset" "$VHD" 2>/dev/null | grep -i 'volume name' | head -1)
    capacity=$(( 10#$len * 512 ))
    echo "slot=$slot  offset=$offset  capacity=$capacity bytes  $label"
done
# Find the row whose Volume Name matches the partition you are looking for.
# Capacity = Length × 512 bytes — use the len from THIS row, not any other.
# NEVER compute capacity from fsstat totals — mmls len × 512 is the only correct method.
#
# CRITICAL: ALWAYS run the FULL loop above to see ALL partitions + their labels.
# NEVER pick the first partition blindly — look for the Volume Name that matches the question.
# Partial match is OK: "J. Wilson" in output matches question asking about "J. Wilson" partition.
#
# WRONG capacity formulas (NEVER use):
#   stat -c "%s" "$VHD"           ← total VHD file size, NOT a partition
#   fsstat output "Total Block Count × Block Size"  ← NOT the same as mmls Length × 512
# RIGHT:  capacity=$(( 10#$len * 512 ))  where $len is the Length column from mmls

# 5. Get cluster size for a specific partition (after finding its start from step 4)
start=<start_from_mmls>
len=<len_from_mmls>
offset=$(( 10#$start ))
capacity=$(( 10#$len * 512 )); echo "Capacity: $capacity bytes"
fsstat -i vhd -o "$offset" "$VHD" | grep -i 'volume name\|cluster size'
# For .vmdk files: fsstat -i vmdk -o "$offset" "$VHD"
```

## Key fields in mmls output

```
GUID Partition Table (EFI)          ← schema on the FIRST line
Offset Sector: 0
Units are in 512-byte sectors

     Slot    Start        End          Length       Description
00:  Meta    0000000000   …            …             Safety Table
01:  -----   …            …            …             Unallocated
02:  Meta    …            …            …             GPT Header
03:  Meta    …            …            …             Partition Table
04:  000     0000000034   <end_sector>   <len_sectors>  Microsoft reserved partition  ← 1st data partition
06:  001     <start_sect>  <end_sector>   <len_sectors>  Basic data partition           ← 2nd data partition
```
- First line = partition schema ("GUID Partition Table" = GPT, "DOS Partition Table" = MBR)
- **Length** × 512 = partition capacity in bytes
- **Start** value → strip leading zeros with `$(( 10#$start ))` → pass as `-o` to `fsstat`

## C — Extracting a file from a VHD partition with icat

**CRITICAL: `icat` takes an INODE NUMBER — NEVER a filename.**
The filename must NOT appear in the `icat` command line. Passing a filename after the inode causes:
  `Invalid inode address: Printers.htm` (the shell splits on spaces and passes words as extra args).

```bash
# Step 1 — find the inode number with fls (filter by filename)
offset=$(( 10#$start ))
INODE=$(fls -i vhd -r -o "$offset" "$VHD" 2>/dev/null \
        | grep -i '<target_filename>' \
        | awk '{print $2}' | tr -d ':')
echo "Inode: $INODE"   # must be a plain number, e.g. 12345

# Step 2 — extract using ONLY the inode — no filename argument after it
icat -i vhd -o "$offset" "$VHD" "$INODE" > /exports/target_file
stat -c "%s" /exports/target_file   # verify non-zero size

# Step 3 — hash if needed
sha1sum /exports/target_file | awk '{print toupper($1)}'
md5sum  /exports/target_file | awk '{print toupper($1)}'
```

WRONG commands that produce `Invalid inode address`:
```bash
# WRONG — filename after inode number
icat -i vhd -o "$offset" "$VHD" 12345 <target_filename>

# WRONG — filename instead of inode
icat -i vhd -o "$offset" "$VHD" '<target_filename>'
```

## Tips
- NEVER retype VHD/VMDK filenames — always use `$VHD` from `find`. Case matters: `SYSTEM.vhd ≠ System.vhd`
- For `.vhd` files always pass `-i vhd` to `fsstat` — without it, TSK reads raw bytes and dynamic VHDs return garbage
- `fsstat -o` requires a DECIMAL offset — use `$(( 10#<start> ))` to strip leading zeros
- To identify a partition by name: run `fsstat` on EVERY data partition, check `Volume Name` — never stop early
- Disk GUID (raw bytes) ≠ partition GUID (UUID bytes_le): the scripts above handle each format correctly
