DESCRIPTION: Query Windows Registry keys. Syntax: reglookup -p '/Key/Path' '/path/to/hive' (flags MUST come before the hive file). The -p filter uses FORWARD SLASHES (/) not backslashes — e.g. '/Microsoft/Windows/CurrentVersion/Run'. Hive paths are case-sensitive on Linux; ALWAYS discover them first with find -iname.

## CRITICAL: Always follow this two-step pattern
1. Discover the exact hive path (case-sensitive filesystem).
2. Run reglookup with flags BEFORE the hive file; use FORWARD SLASHES in -p (never backslashes).

COMPLETE EXAMPLE (both steps in sequence):
```bash
SOFTWARE_HIVE=$(find /forensics/part006 -iname 'SOFTWARE' -not -path '*/Users/*' -not -path '*/diagnostics/*' -not -path '*/RegBack/*' 2>/dev/null | head -1)
reglookup -p '/Microsoft/Windows/CurrentVersion/Run' "$SOFTWARE_HIVE"
```
Replace the hive path in the second command with whatever `find` returned.

NTUSER.DAT discovery:
```bash
find /forensics/part006 -iname 'NTUSER.DAT' 2>/dev/null
```

## What is reglookup?
reglookup is a command-line utility for reading and querying Windows Registry hive files. Unlike RegRipper (plugin-based), reglookup provides raw access to any registry key/value, making it ideal for targeted searches and custom queries.

## Forensic use cases
- Search for a specific registry key path
- Extract all values under a key (e.g., Run keys for persistence)
- Filter registry data by value type (SZ, DWORD, BINARY, etc.)
- Export registry data for timeline analysis
- Investigate specific keys not covered by RegRipper plugins
- Find evidence of program execution, file associations, user settings

## Key flags
- `-p <path>`     — Filter output to keys matching this path prefix
- `-t <type>`     — Filter by value type (SZ, EXPAND_SZ, DWORD, BINARY, MULTI_SZ, etc.)
- `-H`            — Do not print the header row
- `-s`            — Print security descriptors
- `-v`            — Verbose output

## Usage examples
```bash
# Step 1: discover the real hive path (case-insensitive search)
find /forensics/part006 -iname 'SOFTWARE' -not -path '*/Users/*' 2>/dev/null | head -3

# Step 2: use the exact path returned above, e.g.:
SOFTWARE_HIVE=$(find /forensics/part006 -iname 'SOFTWARE' -not -path '*/Users/*' 2>/dev/null | head -1)

# Search for Run keys (autostart programs)
reglookup -p '/Microsoft/Windows/CurrentVersion/Run' "$SOFTWARE_HIVE"

# Search for uninstall entries (installed programs)
reglookup -p '/Microsoft/Windows/CurrentVersion/Uninstall' "$SOFTWARE_HIVE"

# Query NTUSER.DAT for recent documents
NTUSER=$(find /forensics/part006 -iname 'NTUSER.DAT' 2>/dev/null | grep -i 'Jimmy' | head -1)
reglookup -p '/Software/Microsoft/Windows/CurrentVersion/Explorer/RecentDocs' "$NTUSER"

# Save filtered output
reglookup -p '/Microsoft/Windows/CurrentVersion/Run' "$SOFTWARE_HIVE" > /exports/run_keys.txt
```

## Tips
- Use `-p` to narrow results to a specific key path
- Combine with `grep` for further filtering: `reglookup hive | grep -i 'keyword'`
- Use reglookup for targeted queries; use regripper for broad forensic audits
