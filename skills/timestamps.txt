## What is timestamp analysis?
Every file on NTFS has four timestamps: Created, Modified, Accessed, and MFT Entry Changed ($MACE). Forensic timestamp analysis helps build a timeline of events, identify recently created or modified files, and detect timestomping — where an attacker deliberately changes timestamps to hide activity.

## Forensic use cases
- Build a chronological timeline of file activity
- Find files created or modified during a specific time window
- Identify recently accessed documents or executables
- Detect timestomping (e.g., file created after its "modification" date)
- Correlate file activity with login events and program execution
- Find files dropped by malware (unusual creation times)

## Tools
- `stat` — show all timestamps for a specific file
- `find` with `-newer` or `-printf` — search by time range
- `fls` (sleuthkit) — list files with NTFS MFT timestamps (including deleted)
- `istat` (sleuthkit) — detailed metadata for a specific inode
- `mactime` (sleuthkit) — generate a timeline from fls output

## Usage examples
```bash
# Find files modified in a date range — ALWAYS use -printf to include dates in output
find '{evidence}' -type f -newermt '2015-05-24' ! -newermt '2015-05-28' -printf '%TY-%Tm-%Td %TH:%TM %p\n' 2>/dev/null | sort

# Get all timestamps for a specific file
stat '{evidence}/Users/<username>/Documents/<file.txt>'

# Find files with timestamps and sort chronologically (all user files)
find {evidence}/Users -type f -printf '%TY-%Tm-%Td %TH:%TM %p\n' 2>/dev/null | sort | tail -50

# Find files accessed in the last phase of activity (newest first)
find {evidence}/Users -type f -printf '%AY-%Am-%Ad %AH:%AM %p\n' 2>/dev/null | sort -r | head -30

# Search for files created within a specific date range
find {evidence} -type f -newer {evidence}/Windows -not -newer {evidence}/Windows/System32 2>/dev/null | head -30

# Use sleuthkit fls to list files with NTFS MFT timestamps (if available)
fls -r -l '{evidence}' 2>/dev/null | head -50

# Save a full timestamp listing of user files
find {evidence}/Users -type f -printf '%TY-%Tm-%Td %TH:%TM\t%p\n' 2>/dev/null | sort > /exports/file_timeline.txt
```

## Tips
- NTFS stores two sets of timestamps: `$STANDARD_INFORMATION` (shown by stat/Windows) and `$FILE_NAME` (harder to modify). Differences between them can indicate timestomping
- If a file's Modified time is BEFORE its Created time, that is a strong indicator of timestomping
- `find -printf '%TY-%Tm-%Td'` uses modification time; use `%AY` for access time, `%CY` for inode change time
- `fls` with `-l` shows both $STANDARD_INFORMATION and $FILE_NAME timestamps when available
- Always correlate timestamps with other artefacts (event logs, prefetch) to validate findings
